# A Unified Quality Evaluation Platform for Mobile Applications

> **Research Title**: A Unified Quality Evaluation Platform for Mobile Applications through Automated Test Result Aggregation and Visualization  
> **Platform Type**: Full-Stack Quality Reporting & Pipeline Ingestion Platform (React + Express + Node.js)

---

## 📌 Executive Summary & Research Concept

Before releasing a mobile application, QA and Engineering teams run distinct types of automated testing:
1. **Functional / UI Testing** using **Appium** (Pass/Fail counts, locator assertion failures).
2. **Performance / Load Testing** using **Apache JMeter** (Average response latency, throughput, error percentages).
3. **Security Testing** using **MobSF** (Mobile Security Framework static scan vulnerability risks).

Traditionally, project managers, developers, and customers must open **three separate technical reports** to understand whether an app is ready for release.

### The Solution
This platform acts as an **automated translator**. It ingests raw XML, CSV, and JSON report files generated by Appium, JMeter, and MobSF—either via smart **Drag & Drop** or automated **CI/CD Pipeline Webhooks (GitHub Actions / Jenkins)**—aggregates them into a unified database, and computes an overall **Unified Quality Score (0–100%)** presented through role-tailored dashboards.

```text

  │  Appium (UI)    │      │ JMeter (Perf)   │      │ MobSF (Security)│
  │   XML Report    │      │  CSV/JSON Log   │      │   JSON Report   │
  └────────┬────────┘      └────────┬────────┘      └────────┬────────┘
           │                        │                        │
           └──────────────────┬─────┴────────────────────────┘
                              ▼
           ┌─────────────────────────────────────┐
           │ Report Parser & Auto-Detect Engine  │
           └──────────────────┬──────────────────┘
                              ▼
           ┌─────────────────────────────────────┐
           │ Unified Quality Database (db.json)  │
           └──────────────────┬──────────────────┘
                              ▼
           ┌─────────────────────────────────────┐
           │     Interactive Web Dashboard       │
           └──────────────────┬──────────────────┘
                              ▼
 ┌──────────────┬─────────────┴────────────┬──────────────┐
 │ Developer    │ QA Engineer              │ Project Mgr  │ Customer     │
 └──────────────┴──────────────────────────┴──────────────┴──────────────┘
```

## 📊 Core Testing Parameters & Visual Indicators

### 1. Functional / UI Testing (Appium)
* **Core Parameters**: `Total Test Cases`, `Passed Tests`, `Failed Tests`.
* **Visual Clarification**: Rendered via an interactive **Donut Chart** with a thick green slice representing pass ratios and a red slice representing failures.
* **Defect Traceability**: Mapped directly to Version Control Git Metadata (**Commit Hash**, **Branch Name**, and **Code Author**) for immediate developer debugging.

### 2. Performance Testing (Apache JMeter)
* **Core Parameters**: `Average Response Time` (ms), `Throughput` (requests/sec), and `Error Rate` (%).
* **Visual Clarification**: Trends are visualized using a **Sparkline Mini Line Graph** (mini line chart without cluttering axes).
* **Safe Threshold Indicator**: A **Green Checkmark Status Badge** dynamically confirms when the transaction error rate stays below the safe threshold ($\le 2.0\%$).

### 3. Security Testing (MobSF)
* **Core Parameters**: Total vulnerabilities categorized by severity: **High Risks**, **Medium Risks**, and **Low Risks**.
* **Visual Clarification**: Represented via a **Horizontal Stacked Severity Distribution Bar**.
* **Color Coding**: Red (#ef4444) for High, Yellow/Orange (#f59e0b) for Medium, Cyan (#06b6d4) for Low.
* **Actionable Alerts**: A prominent **Red Warning Icon Badge (`🚨 High Risk Alert`)** is placed directly next to High vulnerabilities to immediately highlight critical threats.

### 4. Cross-Cutting Unified Parameters
* **Unified Quality Score**: A single weighted percentage metric calculated as:
  $$\text{Quality Score} = 30\% \cdot \text{UI Score} + 35\% \cdot \text{Perf Score} + 35\% \cdot \text{Security Score}$$
* **Quality Score Gauge**: Displayed as a central **Circular Gauge** with traffic-light color thresholds (Emerald $\ge 90\%$, Amber $75-89\%$, Crimson $<75\%$).
* **Dynamic Release Recommendation Badge**: 
  - `RELEASE READY` (Score $\ge 90\%$ & 0 High Risks)
  - `READY FOR TESTING` (Score $75-89\%$)
  - `NEEDS SECURITY IMPROVEMENTS` (High Risks present)
  - `NEEDS REFACTORING` (Score $<75\%$)

## ⚡ GitHub Actions & CI/CD Pipeline Integration

The platform provides a REST API webhook endpoint for continuous automated report ingestion directly from CI/CD runners.

### Pipeline Ingestion API Endpoint
```http
POST /api/applications/:appId/pipeline/ingest
Authorization: Bearer mqp_pat_:appId_8f3d927a
Content-Type: multipart/form-data
```

### Sample GitHub Actions Workflow (`.github/workflows/mobile-quality-check.yml`)

```yaml
name: Mobile Quality Evaluation Gate

on:
  push:
    branches: [ main, release/* ]
  pull_request:
    branches: [ main ]

jobs:
  quality-gate:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v3

      - name: Run Appium UI Tests
        run: |
          npm run test:appium -- --reporter mocha-junit-reporter --reporter-options mochaFile=./appium_results.xml

      - name: Run JMeter Performance Test
        run: |
          jmeter -n -t ./tests/load_test.jmx -l ./jmeter_results.csv

      - name: Run MobSF Security Scan
        run: |
          curl -F "file=@app-release.apk" http://mobsf-server:8000/api/v1/upload -H "Authorization:${{ secrets.MOBSF_KEY }}" > mobsf_scan.json

      - name: Push Reports to Unified Quality Platform
        run: |
          curl -X POST "http://localhost:8080/api/applications/apex-bank/pipeline/ingest" \
            -H "Authorization: Bearer mqp_pat_apex_bank_8f3d927a" \
            -F "reports=@appium_results.xml" \
            -F "reports=@jmeter_results.csv" \
            -F "reports=@mobsf_scan.json" \
            -F "commitHash=${{ github.sha }}" \
            -F "branchName=${{ github.ref_name }}" \
            -F "author=${{ github.actor }}"
```

## 👥 Stakeholder Persona Views

Toggle between role-tailored views in the top-right corner of the application:

1. **QA Engineer View**: Full manual drag-and-drop ingestion, source file inspection, and database audit logs unlocked.
2. **Developer View**: Unlocks Appium element stack traces, JMeter response time graphs, MobSF patch guidelines, and Git Commit Hash/Branch traceability.
3. **Project Manager (PM) View**: Focuses on high-level quality target thresholds, release readiness recommendations, and build trend charts.
4. **Customer / Client View**: Clean, high-level textual summary suitable for executive presentation without raw technical logs.

## 🛠️ Installation & Local Execution

### Prerequisites
- **Node.js**: v18.0.0 or higher
- **npm**: v9.0.0 or higher

### Steps to Run

1. **Clone or navigate to the project directory**:
   ```bash
   cd mobile-quality-platform
   ```

2. **Install all dependencies** (Root, Backend Express, and Frontend React):
   ```bash
   npm run install-all
   ```

3. **Start the full-stack development environment**:
   ```bash
   npm run dev
   ```
   *This command boots the Express API server on port `8080` and the Vite React server on port `5173` concurrently.*

4. **Access the application**:
   Open your browser and navigate to:  
   🔗 **`http://localhost:5173`**
